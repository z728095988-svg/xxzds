# 熬鹰每分钟监控 · Telegram 版

这是独立后台程序，目标是全天按每 60 秒启动一轮检查，并向绑定的 Telegram 私聊发送仓位净变化。程序已完成，但本交付物不代表服务器已经部署或 Telegram 已经绑定。现有 ChatGPT 每小时任务与这个程序是两个独立任务。

已指定机器人为 [@rdhjvcxsbot](https://t.me/rdhjvcxsbot)。启动时会通过 Telegram getMe 核对 Token 对应的机器人用户名；不匹配会停止运行。这里只保存了你提供的用户名，还没有验证 Token 或绑定你的私人聊天。

## 已实现的行为

- 读取 qwer22.com 已公开的熬鹰币安和 OKX 仓位；不需要交易所 API Key，不执行交易。
- 每 60 秒启动一轮。每轮采样两次，间隔 21 秒。确认仓位变化后提醒；如果上游时间戳更新较慢，会延续到下一轮复核。
- 提醒包括来源、币种、多空、数量变化、北京时间比较区间和原监控页面链接。
- 第一轮只建立基准，不把已有仓位当成新开仓。
- 无变化时保持静默；数据异常、恢复时通知一次。过期或无法解析的数据不会被当作空仓。
- SQLite 持久保存基准、Telegram 绑定和待发送消息。重启后恢复；Telegram 失败会退避重试，遵守 429 的 retry_after。
- 使用一次性随机配对码绑定一个私人聊天；群聊和其他用户不能改绑或查询状态。
- 只暴露不含仓位、接收人和秘密的 `/healthz` 健康检查。

“每 60 秒检查”不等于在交易发生后 60 秒内必达。上游可能延迟，复核和 Telegram 网络也需要时间。快照之间的快速开平仓可能完全看不到。本程序不能还原逐笔交易。

## 现在还缺什么

1. 可持续运行程序的服务器/托管账号（例如 Railway），以及挂载在 `/data` 的持久磁盘。
2. 你通过官方 [@BotFather](https://t.me/BotFather) 创建的专用 Telegram 机器人的 Token。
3. 你亲自向机器人发送配对命令，确认 Telegram 私聊确实属于你。

无需把 Token 发在聊天里、写进代码或上传 Git。请直接在服务商的安全变量中填写。机器人用户名可以分享，Token 不可以公开。

## 创建 Telegram 机器人

1. 打开 [官方 BotFather](https://t.me/BotFather)，发送 `/newbot`。
2. 根据提示设置名称及以 `bot` 结尾的用户名。
3. 保存 BotFather 返回的 Token，在托管服务的变量页面配置 `TELEGRAM_BOT_TOKEN`。
4. 使用新的专用机器人。程序发现机器人已配置其他 Webhook 时会暂停配对，不会擅自删除 Webhook。

官方说明：[创建机器人](https://core.telegram.org/bots/tutorial#obtain-your-bot-token)、[Bot API](https://core.telegram.org/bots/api)。

## 部署到 Railway

将本目录作为独立服务的源码根目录（也可把这些文件放到你自己的私有 Git 仓库）。根目录已包含 Dockerfile 和 railway.json。

1. 使用普通常驻服务，单副本，关闭 Serverless/休眠。**不要设置 Railway Cron**：其最小间隔是 5 分钟，不满足本任务。
2. 挂载一个持久 Volume 到 `/data`。没有持久磁盘，重建服务会丢失绑定、基准与重试队列。
3. 在服务的 Variables 中填写以下变量；把敏感值设为密封/秘密变量，不打印到日志。

| 变量 | 值 |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | BotFather 返回的 Token |
| `TELEGRAM_PAIR_CODE` | 自己生成的 32–64 位随机字符，仅使用英文字母、数字、`_`、`-` |
| `DATA_DIR` | `/data` |
| `PORT` | 使用平台提供的 PORT；未提供则 8080 |

4. 启动命令是 `node src/worker.mjs`。Docker 中已配置，无需 npm install，没有第三方 npm 依赖。
5. 等服务日志显示“Telegram 机器人验证通过”，在你的机器人私聊中发送 `/start 你的配对码`。不要把配对码放入公开群、代码、日志或分享链接。
6. 机器人回复绑定消息后，等待币安、OKX 的“基准已建立”消息。确认收到后，用 `/status` 查看最后检查时间；至少核对两轮检查约相隔 60 秒。
7. 真实上线后再停用原来 ChatGPT 的每小时任务，避免两个通道重复提醒。本次交付没有改动原任务。

Railway 费用取决于你的账号和资源使用情况。本包未创建任何 Railway 资源，也未订购套餐。

官方部署资料：[常驻服务](https://docs.railway.com/services)、[Volume](https://docs.railway.com/volumes)、[变量](https://docs.railway.com/variables)、[Cron 限制](https://docs.railway.com/cron-jobs)。

## 自有服务器运行

需要 Node.js 24。先通过安全环境变量配置 Token、配对码和数据目录，再执行：

```bash
npm test
npm run check-source
npm start
```

也可以构建 Docker 镜像运行，需把持久目录挂载到 `/data` 并设置自动重启。`check-source` 只验证公开数据源，不发送 Telegram 消息。

## 检查与恢复

- `/status`：仅已绑定的私人聊天可用，返回最近完成检查时间、数据源状态和发送队列长度。
- Telegram 提示没有变化时，程序不发例行消息。首次基准消息和手动 `/status` 回复是例外。
- 若机器人被你屏蔽、Token 失效或 Telegram 限流，队列保留；解除问题后继续尝试。通知中仍保留原比较区间，不将积压提醒冒充新成交。
- 数据源异常时保留最后有效基准；恢复后展示跨越空档的比较区间。
- 绑定写入持久数据库。更换 Token 后只接受同一个机器人身份；不要借用已有其他业务的机器人。
- 单副本运行。数据库租约可以防止同一数据库被两个实例同时使用，但不能协调两块独立磁盘。
- 已获 Telegram API 接受的消息不会在正常重启时重发。网络超时、或 API 已成功但落盘前进程崩溃的极端情况，重试可能产生重复消息；不声称“绝不重复”或“保证送达手机”。
- `healthz` 只能证明程序在运行，不能证明手机通知权限已打开。还需在手机和 Telegram 中允许该机器人通知。
